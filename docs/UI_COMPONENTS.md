# iOS / Android UI 组件行为对照（0.1.3）

2026-10-22。在当前 main 分支修改 Android；未运行格式化工具，未修改 iOS。六个专项并行对照，并与「规划原生安卓版本迁移」明确交接 UI 文件。

本表覆盖 iOS App / Components / DesignSystem / Features 下的全部 Swift 文件，包括 UI 支撑类型。覆盖指源码职责和行为核对，不代表每一个布局、设备和交互组合均已自动验证。测试及人工观察结论见 [验收记录](ACCEPTANCE.md)。

第二轮补齐保存等待、目录状态、编辑历史、日期选区、大纲和日期刷新，见 [0.1.3 功能对齐补充](FUNCTION_PARITY-0.1.3.md)。

## 设计决策

保留 Material 3 导航条/轨道、TopAppBar、原生菜单、BottomSheet、DatePicker/TimePicker、文本输入、Checkbox、Switch、Snackbar 和动态色；对齐入口、信息结构、选择、草稿、保存、取消、定位与恢复行为。图片、公式和源码继续使用现有原生库，不增加自绘系统控件或 Liquid Glass。

依据 [Material 3 in Compose](https://developer.android.com/develop/ui/compose/designsystems/material3) 与 [Compose accessibility defaults](https://developer.android.com/develop/ui/compose/accessibility/api-defaults) 保留平台组件、触摸目标和语义。

## 根层补齐

启动显示进度并暂时禁用操作，失败时给出重试和选择文件夹入口；切页等待当前文档保存完成。系统 New task 始终进入无指定日期的 Capture，Today 重置日历，Search 清空并聚焦，Files 回根目录。所有已登记的模态界面关闭后才处理快捷操作；普通 Activity 启动 Intent 不关闭已打开文档。

Root 和主要输入表单保存旋转所需的可见状态与草稿，源码阅读位置由模型保存。对源事项的引用恢复要求工作区及原文版本仍一致，避免旋转后按过期偏移写入。

## 保留的平台差异与验证边界

Android 设置保留独立导航目的地；工作流和模板操作使用显式菜单，拖放亦提供非手势入口。日历大字号布局、Habit 网格、系统文本菜单、主题和动画遵从 Android。代码高亮语言集合不同；未支持语言显示原文。源码对照与模拟器回归不能替代真机 TalkBack、真实中文输入法、厂商分屏/休眠和真实云存储验证。
